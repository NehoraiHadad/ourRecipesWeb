# ניסוי ממוקד לשיפור קישור דיווח לפעולה

התוכנית קובעה לפני הריצה ב־`verification/targeted-plan-20261111.json`.

## ההשערה

נמצאו עדכונים עודפים: למשל דיווח על שטיפת מרכיב שימש גם כראיה לערבובו. האימון הקודם פיקח על תגיות המילים; בשאילתות פעולה הוא לא פיקח בנפרד על החלטה ברמת זוג הדיווח והפעולה.

נבדוק שילוב של החלטת זוג מפורשת וחילוץ ציטוט. עדכון דורש הסכמה על ביצוע/שלילה בשני החלקים. ״פעולה לא דווחה״ היא תשובה חוקית, גם כשמוזכר אותו מרכיב. בדוגמאות ללא ראיה מקומית ניתן משקל מלא לשלילה זו, במקום משקל רקע של 0.15.

## שתי הריצות

- **ביקורת:** DictaBERT רגיל, הנתונים וה־loss הקודמים, עד 1,000 צעדים.
- **שיפור ממוקד:** אותו מודל בסיס, זרע 42, אצווה 8 וקצבי למידה; החלטת זוג + ציטוט, ניגודים באותו מרכיב/באותו פועל, ושאלות/תכנון/דיווח חלקי. עד 1,500 צעדים.

אימות ושמירת המודל הטוב בכל 250 צעדים. נקודת 1,000 נשמרת בדוחות להשוואה תואמת; הרחבת 500 הצעדים מדווחת בנפרד. זו התערבות משולבת, ולכן אין להסיק איזה משינויי הנתונים וה־loss לבדו גרם לתוצאה. לא נחליף במקביל מודל בסיס, קצב למידה או seed.

## בחירה והצלחה

בחירה בין מועמדים משתמשת באימות בלבד: מעדיפים כיסוי של לפחות 88%, ואחריו דיוק עדכוני פעולה, התאמה מלאה עם ראיות וכיסוי. שיפור מהותי לעומת הביקורת ידרוש לפחות שלושה עדכונים שגויים פחות, ירידת כיסוי של עד ארבע נקודות אחוז ודיוק עדכונים של לפחות 95%.

רף לשימוש אוטומטי נשאר מחמיר ונפרד: לפחות 99% דיוק וכיסוי 80%, ציטוטים נכונים, התאמת הרצות ובדיקות חדשות. הימנעות מכל עדכון אינה הצלחה. קבוצת המבחן המקורית לא תשמש לבחירה.

16 מקרי אבחון חדשים בשני מתכונים קובעו מראש. הם וקבוצת הרגרסיה הישנה נבדקים רק אחרי בחירת המודל ונקודת האימון. הם מלאכותיים וטרם נבדקו בידי אדם; אין כאן טענת דיוק על שיחות טבעיות.

## משאבים והרצה מקומית

T4 אחד, עד 1,200 שניות לעבודה המרוחקת ועד 800 להשוואת האימון. מאמנים את שתי הגרסאות באותה סביבה. משחזרים רק את משקולות המועמד שנבחר ואת הדוחות. העברה ב־SSH בינרי תיבדק ב־SHA-256; נשמר מסלול גיבוי של חלקים מאומתים. מפתחות והרשאות נשארים מחוץ למאגר ואינם עולים ל־Colab.

לא מבצעים ייצוא ובדיקות CPU ממושכות עם GPU מוקצה. אחרי הורדה ושחרור GPU נבדוק native ORT ‏1.30.0 מול ORT Web ‏1.30.0 בסביבה מקומית מבודדת, כדי להסיר את פער הגרסאות מהבדיקה הקודמת. השוואת גרסאות אינה מבטיחה התאמה: תוצאות native/WASM יימדדו בפועל.

## שחזור

הפקודות מתחילות בתיקייה הזו. נדרשים Colab CLI מאומת ומפתח SSH מקומי מורשה; המפתח נשאר במחשב המפעיל. שם הסביבה ותיקיית הפלט צריכים להיות חדשים. זו פקודה שמקצה T4 בפועל:

```bash
python3 colab_pilot.py --cli colab \
  --session ourrecipes-targeted-new --run-id ourrecipes-targeted-new \
  --output runs/targeted-new --targeted --steps 1500 --max-seconds 1200 \
  --ssh-identity /path/to/local/ssh-key
```

הדרייבר משחרר את הסביבה ב־`finally`, גם בכשל רגיל או SIGTERM. אין הבטחת ניקוי אחרי SIGKILL או אובדן המחשב המפעיל: יש לבדוק `colab sessions`, לשחזר תוצאות מסביבה קיימת ולסגור אותה, בלי להקצות GPU נוסף. אין להעביר מפתחות או קובצי התחברות ל־Colab או ל־Git.

בדיקות מכניקה ללא GPU: `python3 -m unittest discover -s tests -p 'test_*.py'`. בדיקת שני צעדים עם משקולות tiny אמיתיות: `python targeted_sweep.py runs/cpu-mechanics --cpu-smoke --steps 2 --max-seconds 180`. זו אינה בדיקת איכות.

לייצוא אחרי שחרור ה־GPU, מתקינים את `requirements-export.txt` בסביבת Python נפרדת שמכילה גם Torch ויתר תלויות `requirements-py313.txt`, תוך שימוש בגרסת ORT מה־overlay. מריצים `span_pilot.py RUN --reexport`, אחריו `span_evaluate.py RUN --onnx-fp32`, ואז `span_evaluate.py RUN --make-browser-fixtures` ו־`node browser-smoke.mjs RUN/onnx`. כאן `RUN` הוא נתיב `recovered/run`. אין להריץ מבחן סופי אם שער האימות נכשל.

הדרך שנבדקה ליישור ORT בלי לשנות את סביבת האימון היא התקנה ל־target נפרד על גבי סביבת Python 3.13 שכבר מכילה את תלויות האימון:

```bash
uv pip install --python /path/to/py313/bin/python \
  --target runs/ort130 --no-deps -r requirements-export.txt
PYTHONPATH="$PWD/runs/ort130" /path/to/py313/bin/python \
  span_pilot.py runs/targeted-new/recovered/run --reexport
```

משתמשים באותו `PYTHONPATH` גם להערכת `span_evaluate.py`. אין למסור ל־pip את שני קובצי הדרישות יחד: הם מקבעים בכוונה גרסאות ORT שונות. לבדיקת מסלולים שמציעים עדכון גם כשהמדיניות המכוילת נמנעת, יוצרים `span_evaluate.py RUN --make-diagnostic-browser-fixtures` ומריצים `node browser-smoke.mjs RUN/onnx RUN/diagnostic-browser`. הסף 0.5 שם הוא בדיקת ניידות בלבד, לא שינוי מדיניות מוצר.
