# What was actually verified

Checked 2026-11-11 on the cloud Linux workspace. This is a **training material package**, not a released cooking model.

- **25 stdlib unit tests:** recipe/exact-utterance split leaks, synthetic provenance, invalid state/IDs/evidence, partial/correction labels, ambiguous and prior-recipe examples, confidence abstention, over-completion metrics, task-specific masks, human-review import and notebook syntax. Six Colab control tests cover cleanup, session isolation, bundle hash/path checks and read-only poll retries. New tests cover candidate-order invariance, train-only augmentation/holdout byte preservation, balanced sampling, span grounding/history exclusion/conflicting clauses, fine-grid coverage and preservation of best-validation weights. Resource controls and best-weight selection use mocks; they are not new live GPU runs.
- **Actual pinned DictaBERT weights, CPU:** two optimizer steps using PyTorch 2.6.0+cpu / Transformers 4.48.3 / Python 3.12.14. Forced interruption after the first completed checkpoint and resumption produced exactly the same safetensors SHA-256 as an uninterrupted two-step run. `verification/cpu-resume.json` records the source and corpus hashes. This is a mechanics test, not a useful trained model.
- **Actual native ONNX export:** 179,151,172 B FP32, 44,973,125 B reduced-range INT8, plus tokenizer/runtime. Four tensor batches, ten queries, dynamic batch/sequence axes. FP32 numerical parity and task-masked label agreement on these fixtures. Full semantic quality must be evaluated after a real training run.
- **Actual browser graph inference:** headless cloud Chromium 156, ORT Web 1.30.0 WASM, one thread. On the tested INT8 artifact, load ~191 ms and tensor batches of 1–4 queries ~27–55 ms. These are cached/local server measurements on an undertrained model; not download time, tokenizer time, full recipe conversation latency, or physical phone measurements.
- **Native vs browser:** zero label/confidence-decision disagreements in the fixtures. FP32 max logit drift ~1.23e-7. INT8 max drift ~0.0039, despite matching decisions. Different native/WASM quantized kernels can differ numerically; the harness records drift and checks decisions. This small check does not certify all input shapes or semantic accuracy. The browser used Python-pretokenized inputs, so browser tokenizer parity remains untested.
- **Real native INT8 validation plumbing:** 120 validation conversations were scored. After only two training steps, the selected conservative threshold resulted in **zero proposed updates and zero update recall**. It is not usable. This confirms the reports do not confuse an abstain-on-everything model with a successful assistant. The 120 held-out **test** conversations were not used for these checks.
- **Modal:** SDK 1.6.3 import/decorator validation and CLI argument help were checked locally. No account authentication, image build, remote CPU/GPU call, credit use or provider billing measurement. The launcher's CPU prefetch and GPU/Volume behavior still require the first explicit account run.
- **Colab, actual T4:** the official `google-colab-cli` 0.8.0 was installed, its official operator skill read, and OAuth completed with the user's authorization. The bounded CLI runner uploaded original synthetic material and executed 200 steps on Python 3.12, plus matched fresh 200/1,000-step runs on Python 3.13.16. The 1,000-step training loop took 99.41 s, peak PyTorch allocated CUDA memory 922,761,216 B. Installation, validation, export and recovery are additional time. A separate attempt failed during dependency setup after a CLI monitoring timeout, before training; retry behavior was fixed and unit-tested. All dedicated VMs were stopped and zero active assignments/consumption rate verified. No Drive mount, user recordings or production recipe upload occurred. Credentials remain owner-only outside the repository. A rounded aggregate balance decrease (~0.26 CU) is an observation across the sequence, not a precise per-run bill or free-tier claim.
- **Actual trained-model validation:** at threshold 0.5 the 1,000-step model produced 63/120 exact proposals, 53 action updates including 17 wrong (precision 67.9%, recall 42.4%). The conservative selected threshold 0.8 produced zero updates and 120 clarifications. Native INT8 validation also abstained throughout with the selected policy. **Not usable; no model adoption claim.** This does not isolate base-model quality from data, architecture or confidence-policy effects. The held-out test was not evaluated.
- **Actual trained-model browser inference:** the exported 1,000-step model ran in cloud Chromium 156 / ORT Web 1.30.0 / single-thread WASM using four Python-pretokenized fixture batches (ten queries). INT8 local load ~353 ms, batches ~31–60 ms; zero masked label/confidence-decision disagreements. FP32 maximum logit drift ~2.65e-6; INT8 ~0.091. These remain graph compatibility checks, not browser-tokenizer parity, full semantic validation or physical-device latency. No external HTTP requests were observed by the harness.
- **Python 3.13 compatibility:** actual CPU training/resume equivalence, ONNX export and browser graph checks with Python 3.13.17, plus the above T4 runs with Python 3.13.16. Updated NumPy/ONNX/ORT wheels are pinned in `requirements-py313.txt`; Torch remains 2.6.0 for comparison. Colab runner/notebook default to 3.13; 3.12 remains reproducible. Modal retains its original 3.12 profile.
- **Colab notebook UI:** notebook JSON and all Python cells were parsed, with no saved outputs/execution counts. The GUI notebook itself was not run; the cloud job was run through CLI.
- No production application, timer, Capacitor or native mobile file was modified in this training follow-up. No user recordings or production recipe records were collected. Training data remains synthetic and not human-reviewed; no physical phone or human cooking/listening evaluation was performed.

Raw compact evidence is in `verification/materials.json`, historical `cpu-resume.json`, `browser.json`, `export.json`, and new `colab-pilots-20261111.json`, `py313-cpu.json`, `py313-browser.json`. The original two-step/browser records above remain historical mechanics checks; the trained-model results are reported separately. See [Hebrew results](COLAB_RESULTS.he.md). Model weights/checkpoints and private account usage logs are excluded from Git and the material ZIP. The export report precedes the separate browser harness; it does not claim that the exporter ran a browser.
